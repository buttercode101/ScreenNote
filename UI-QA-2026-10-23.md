# ScreenNote v0.1.3 UI and resilience review

## Fixed defects

- At 320 CSS pixels the cloud-delete dialog placed Cancel outside the left edge. Buttons and dialog actions now wrap, and flex children can shrink.
- Long guest names overflowed reply cards. Titles, names, replies and controls now wrap inside their containers. Editor headings show the actual escaped recording title.
- The hidden emergency-download placeholder appeared during ordinary capture because button CSS overrode the browser's hidden rule. An explicit hidden rule fixes this.
- Repeated failed recovery writes scrolled the page each second, making Stop unreliable to click. A serialized writer warns once and abandons further recovery writes after failure; in-memory capture continues. Three regression tests cover ordering, failure and flush behavior.
- A video that could not be saved locally could be lost by internal navigation. Its download now remains on local screens, closing the tab triggers a warning, and starting another recording requires acknowledging that the copy was saved.
- Cancel/Escape could dismiss a dialog during an owner mutation. Dialogs now disable their controls, prevent cancellation while saving and guard other navigation.
- Pause now explicitly announces that capture is paused. Stop disables itself while saving. Notices do not intercept clicks.
- Viewer reaction selection survives reload. Malformed viewer links show an unavailable page. The storage-error screen has a working skip target.
- Clean builds remove stale output, including internal QA fixtures.

## Verification

- 35 automated tests pass, including three new recovery-write regressions. Production build and JavaScript syntax checks pass.
- Final pass: 340 responsive layout assertions across 20 screen/state combinations at 17 widths (320, 360, 390, 480, 481, 600, 767, 768, 834, 835, 1024, 1025, 1150, 1151, 1600, 1601, 1920). Zero document overflow or out-of-bounds/overflowing key controls. Includes local/shared/recovered/offline editors, library, unavailable/storage-error views, viewer with 100-character title/40-character name/500-character reply, rename/removal/interrupted dialogs, emergency download retained on library/privacy, alternate theme and 360px landscape height. Earlier targeted checks also covered cloud deletion, revocation, clipboard fallback, recording, upload failure, privacy and recovery in light/dark themes.
- Actual local browser behavior: empty-title rejection, literal-text rename, invalid trim rejection, valid trim to a separate record, download, recovery-key validation/import/export, local-file preservation on key import, owner dialog cancellation/submit, delayed mutation with Cancel and Escape blocked, copy-link success/fallback, three reactions and toggling, literal-text replies and timestamp playback seeking.
- A real trimmed download was inspected with ffprobe: 3.000 seconds, VP8 video and Opus audio, 176,226 bytes. Original remains saved separately.
- Generated screen/camera/microphone/system-audio streams exercised real MediaRecorder and compositing. Pause/resume/stop produced a saved playable local recording. Simulated permission refusal fails visibly without publication.
- Simulated storage-quota failure: Stop remained clickable, a captured file downloaded (1.276 seconds, VP8/Opus, 31,186 bytes), and the emergency link survived navigation to Privacy and library. New recording stayed disabled until acknowledgment. Interrupted saved chunks recovered into a seven-second editor recording. A Chromium WebM can produce ffprobe's unknown-sized-element warning; decoding and playback succeed.
- Simulated offline service disables publication while keeping download available. Simulated upload failure retains the video and allows retry/download. Slow requests and clipboard rejection render actionable feedback.

## Boundaries

Responsive checks use CSS-pixel iframes, not physical phones. Capture inputs and failure services in the matrix are simulations; native screen pickers and real camera/microphone permissions on Chrome/Safari/Android/iOS remain device acceptance work. Earlier release reports contain live private Blob upload/view/reply/revoke/delete evidence; the UI matrix does not substitute for those integrations. No finite test establishes zero failures on every browser or device.

This remains an early-access deployment: 16 shared reservations, five-minute/25 MB clips, seven-day links, demand-driven capacity cleanup and five-minute residual access for already issued playback URLs. Export recovery keys before losing browser data; video downloads are separate backups. No proprietary Pixlr code or deployment was modified.
